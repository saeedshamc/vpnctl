# vpnctl

> ترافیک **لینوکس** را از VPN گوشی **اندروید**، از طریق USB عبور دهید.
> بسته‌های انتشار همراه ابزارها، آیکون tray، CLI و رابط وب محلی هستند؛ میزبان همچنان به اجزایی مثل `iproute2`، پشتیبانی TUN، systemd/polkit و مرورگر نیاز دارد.

**زبان‌ها:** [English](README.md) · فارسی

**وضعیت پیاده‌سازی:** فازهای الزامی **۰ تا ۷ پیاده‌سازی شده‌اند**؛ فاز ۸ اختیاری هنوز شروع نشده است. تست و vet زبان Go، بازگردانی مسیر در network namespace، fuzz کردن IPC، build لینوکس و ساخت آزمایشی بسته‌ها موفق بوده‌اند. **آزمون پذیرش باقی‌مانده:** نصب/استفاده/حذف روی Debian تازه، آزمایش با گوشی واقعی اندروید، بررسی نهایی مجوز اجزای ثالث و انتشار نسخه‌دارِ امضاشده.

## ۱. برنامه چه می‌کند

</div>

```
 لپ‌تاپ لینوکس                                    گوشی اندروید
┌──────────────────────────────────┐   USB    ┌──────────────────────────────┐
│ apps → tun0 → tun2socks → 127.0.0.1:L ──────┼─► adb forward ─► 127.0.0.1:P │
│        (default route, DNS, IPv6)│  cable   │   v2rayNG (VPN app, SOCKS)   │
└──────────────────────────────────┘          │            │                 │
                                              │            ▼                 │
                                              │       VPN server → Internet  │
                                              └──────────────────────────────┘
```

<div dir="rtl">

* روی گوشی یک کلاینت VPN اجرا می‌شود که یک پروکسی SOCKS5 محلی باز می‌کند (در v2rayNG: `127.0.0.1:10808`).
* `vpnctl` آن پورت را با `adb` از طریق USB به لپ‌تاپ می‌آورد، یک رابط مجازی `tun0` می‌سازد و با `tun2socks` **همه‌ی** ترافیک لپ‌تاپ را از آن عبور می‌دهد.
* لپ‌تاپ نه اکانت VPN می‌خواهد، نه کانفیگ، نه v2ray. اتصال واقعی را گوشی انجام می‌دهد.
* پورت پیش‌فرض در هر دو طرف `10808` (SOCKS) است. هر دو قابل تغییرند، ولی فقط وقتی خودتان بخواهید.

## ۲. اهداف و غیراهداف

**اهداف**

* اتصال و قطع با یک دستور یا یک کلیک، بدون هیچ ردپای باقی‌مانده بعد از آن.
* امن به‌صورت پیش‌فرض: اگر هر چیزی خراب شد، اینترنت عادی لپ‌تاپ باید خودکار برگردد.
* قابل نصب روی سیستمی که **اینترنت ندارد** (هر چیز لازم داخل بسته است).
* ظاهر بومی برای دسکتاپ لینوکس: ورودی در منوی برنامه‌ها، قابل جستجو، آیکون tray، پنجره‌ی رمز polkit.
* رفتار یکسان در CLI، tray و رابط کاربری (هر سه از یک موتور مشترک استفاده می‌کنند).

**غیراهداف**

* خود یک کلاینت VPN نیست (vmess/vless/trojan نمی‌فهمد). این کار با اپ گوشی است.
* مدیر adb یا درایور برای همه‌ی مدل‌های گوشی نیست.
* پشتیبانی از iOS در نسخه‌ی ۱ نیست.
* پشتیبانی از ویندوز و macOS در نسخه‌ی ۱ نیست.

## ۴. معماری

چهار باینری کوچک با یک موتور مشترک:

</div>

```
vpnctl-gui  (user)  ──┐   tray + local web UI server
vpnctl      (user)  ──┼──►  unix socket /run/vpnctl/vpnctl.sock  ──►  vpnctld (root)
vpnctl-installer ─────┘                                              ├─ adb forward
                                                                      ├─ tun0 + tun2socks
                                                                      ├─ routes / DNS / IPv6
                                                                      ├─ watchdog
                                                                      └─ state file + cleanup
```

<div dir="rtl">

| باینری | اجرا با | کار |
|---|---|---|
| `vpnctld` | **root** | تنها بخش دارای دسترسی ویژه. adb، tun، route، DNS، IPv6 و watchdog را انجام می‌دهد. روی یک سوکت یونیکس گوش می‌دهد. |
| `vpnctl` | کاربر عادی | CLI. دستورها را به `vpnctld` می‌فرستد؛ اگر در حال اجرا نبود آن را با `pkexec` بالا می‌آورد. |
| `vpnctl-gui` | کاربر عادی | آیکون tray + یک سرور HTTP کوچک روی `127.0.0.1` که رابط وب تعبیه‌شده را سرو می‌کند. پنجره را (در حد امکان به‌صورت *app mode* بدون تب و نوار آدرس) در مرورگر کاربر باز می‌کند. |
| `vpnctl-installer` | کاربر عادی (برای نصب فایل‌ها از pkexec استفاده می‌کند) | entrypoint نصب داخل آرشیو portable؛ پس از کپی فایل‌های همراه، رابط اجرای اول را باز می‌کند. |

فقط `vpnctld` دسترسی root دارد. باگ در رابط یا CLI نمی‌تواند مستقیم به تنظیمات شبکه دست بزند.

### پکیج‌های داخلی (Go)

</div>

```
internal/config     load/save/validate config.toml
internal/adb        run bundled adb, device state, forward, authorise
internal/tunnel     create tun, supervise bundled tun2socks
internal/netcfg     routes, DNS (systemd-resolved), IPv6 sysctl, snapshot + restore

internal/install    install/uninstall logic shared by wizard and .deb scripts
```

## ۵. منطق اتصال، watchdog و بازیابی

### ۵.۱ دستور `up` (تکرارپذیر / idempotent)

1. اگر قبلاً وصل است: کاری نمی‌کند و فقط وضعیت را گزارش می‌دهد. اگر نیمه‌وصل است: اول پاکسازی می‌کند.
2. گوشی را چک می‌کند: وضعیت `adb` باید `device` باشد (نه `unauthorized` یا `offline`).
3. `adb forward tcp:LOCAL tcp:PHONE`.
4. **قبل از دست زدن به هر چیز، پروکسی را تست می‌کند**: `test_url` را از `socks5h://127.0.0.1:LOCAL` می‌گیرد. اگر شکست خورد، با پیام روشن متوقف می‌شود و شبکه‌ی لپ‌تاپ دست‌نخورده می‌ماند.
5. وضعیت فعلی شبکه (default routeها، DNS، تنظیم IPv6) را در `state.json` ذخیره می‌کند (snapshot).
6. `tun0` را می‌سازد، `198.18.0.1/15` می‌دهد، `tun2socks` بسته‌بندی‌شده را اجرا می‌کند و صبر می‌کند تا واقعاً بالا بیاید.
7. فقط بعد از آن: default route با `dev tun0 metric 1`، DNS روی `tun0` (DNS-over-TLS) و در صورت تنظیم، خاموش کردن IPv6.
8. IP خروجی و کشور را گزارش می‌دهد.

### ۵.۲ دستور `down`

route را حذف می‌کند، `tun2socks` را متوقف می‌کند، DNS را برمی‌گرداند، `tun0` را پاک می‌کند، IPv6 را برمی‌گرداند و `adb forward` را برمی‌دارد. بر اساس snapshot انجام می‌شود، پس حتی اگر در این فاصله چیزی عوض شده باشد درست کار می‌کند.

### ۵.۳ Watchdog

هر چند ثانیه چک می‌کند: گوشی هنوز `device` است؟ `tun2socks` زنده است؟ پروکسی جواب می‌دهد؟ اگر نه، خودکار `down` انجام می‌دهد، اعلان نشان می‌دهد و آیکون tray را روی *error* می‌گذارد. اگر کابل کشیده شود، اینترنت لپ‌تاپ بی‌صدا قطع نمی‌ماند.

### ۵.۴ بازیابی بعد از کرش

`vpnctld` فایل `state.json` را می‌نویسد. هنگام شروع (و در `ExecStopPost` / `--cleanup`) هر وضعیت باقی‌مانده قبل از هر کار دیگری برگردانده می‌شود.

## ۶. تنظیمات

مسیر: `~/.config/vpnctl/config.toml` (پیش‌فرض سیستمی: `/etc/vpnctl/config.toml`). نمونه: [`packaging/config.example.toml`](packaging/config.example.toml).

| کلید | پیش‌فرض | معنی |
|---|---|---|
| `phone_port` | `10808` | پورت پروکسی روی گوشی |
| `local_port` | `10808` | پورت فوروارد‌شده روی لپ‌تاپ |
| `proxy_type` | `socks5` | `socks5` یا `http` |
| `dns` | `1.1.1.1, 8.8.8.8` | سرورهای DNS هنگام اتصال |
| `dns_over_tls` | `true` | DNS روی TCP/TLS (بخش ۱۱) |
| `disable_ipv6` | `true` | جلوگیری از نشت IPv6 |
| `test_url` | `https://github.com` | آدرس تست سلامت پروکسی |
| `launch_at_login` | `true` | tray با ورود به دسکتاپ اجرا شود |
| `auto_connect` | `false` | به‌محض دیده شدن گوشی وصل شود |
| `helper_at_boot` | `true` | `vpnctld` به‌صورت سرویس systemd اجرا شود (بدون پرسیدن رمز) |

## ۷. راهنمای CLI

</div>

```bash
vpnctl up      [--phone-port N] [--local-port N] [--proxy socks5|http]
vpnctl down
vpnctl status  [--json]        # state, exit IP, country, uptime
vpnctl test                    # probe only; changes nothing
vpnctl config  get|set <key> [value]
vpnctl logs    [-f]
vpnctl service enable|disable  # systemd helper at boot
vpnctl autostart enable|disable
vpnctl uninstall
vpnctl version
```

<div dir="rtl">

کدهای خروج: `0` موفق · `2` مشکل گوشی/adb · `3` پروکسی مرده · `4` شکست در تنظیم شبکه (قبلاً برگردانده شده) · `5` دسترسی رد شد.

## ۸. Tray و رابط کاربری

### Tray (مثل PdaNet ویندوز)

* بی‌صدا شروع می‌شود؛ فقط یک آیکون دیده می‌شود.
* وضعیت آیکون: خاکستری = قطع، نارنجی = در حال اتصال، سبز = وصل، قرمز = خطا (`assets/tray/`).
* راست‌کلیک: **Connect / Disconnect · Open · Settings · Quit**.
* کلیک چپ: باز شدن پنجره. بستن پنجره آن را مخفی می‌کند و برنامه در tray می‌ماند.
* فقط یک نمونه اجرا می‌شود؛ اجرای دوباره بدون ساخت tray دوم خارج می‌شود.

### پنجره (رابط وب محلی)

* **داشبورد:** اتصال/قطع، آزمایش پروکسی گوشی، وضعیت، IP خروجی و کشور و مدت اتصال.
* **تنظیمات:** پورت‌ها، نوع پروکسی، DNS، DNS-over-TLS، IPv6، URL تست، سطح لاگ، *اجرا هنگام ورود*، *helper هنگام بوت* و *اتصال خودکار*.
* **لاگ‌ها:** نمایش زنده‌ی لاگ.
* **ویزارد اجرای اول:** بخش ۹.۳.
* فقط HTML/CSS/JS ساده (بدون فریم‌ورک، بدون CDN، آفلاین کار می‌کند). تم تیره هماهنگ با لوگو.

امنیت سرور رابط: فقط روی `127.0.0.1`، پورت تصادفی، توکن مخصوص هر نشست، بررسی سخت‌گیرانه‌ی `Host` و `Origin`، بدون CORS.

> tray به دسکتاپی نیاز دارد که StatusNotifierItem را پشتیبانی کند: Cinnamon، KDE، XFCE، MATE و دیگران پشتیبانی می‌کنند. GNOME خالص به افزونه‌ی *AppIndicator* نیاز دارد. اگر tray وجود نداشت، `vpnctl-gui` مستقیم پنجره را باز می‌کند.

## ۹. نصب‌کننده و بسته‌بندی

### ۹.۱ خروجی‌ها

| فایل | کاربرد |
|---|---|
| `vpnctl_<ver>_amd64.deb` | **هدف اصلی.** بعد از دریافت باینری‌های نسخه‌دار، نصب آفلاین است. |
| `vpnctl_<ver>_linux_amd64.tar.gz` | آرشیو portable شامل installer، باینری‌های برنامه و ابزارهای دریافت‌شده. |
| `SHA256SUMS` | checksumهای SHA-256 فایل‌های خروجی؛ امضای انتشار هنوز تنظیم نشده است. |

هدف فعلی bundle و بسته Debian فقط Linux/amd64 است. `vpnctl-installer` یک entrypoint در آرشیو portable است، نه installer تک‌فایلی self-extracting.

### ۹.۲ محتوای فایل deb

</div>

```
/usr/bin/vpnctl                 /usr/bin/vpnctl-gui
/usr/lib/vpnctl/vpnctld         /usr/lib/vpnctl/tun2socks     /usr/lib/vpnctl/adb
/usr/share/doc/vpnctl/           مجوز پروژه و NOTICE ابزارهای Android
/usr/share/applications/vpnctl.desktop
/usr/share/icons/hicolor/{16..512}x../apps/vpnctl.png   + scalable/apps/vpnctl.svg
/usr/share/polkit-1/actions/org.vpnctl.daemon.policy
/lib/systemd/system/vpnctld.service
/etc/vpnctl/config.toml
```

<div dir="rtl">

بسته فایل‌ها را بدون دانلود نصب می‌کند. `prerm/postrm` سرویس را متوقف می‌کنند، تلاش می‌کنند شبکه را برگردانند و systemd را reload می‌کنند؛ `purge` فایل تنظیم سیستم را هم پاک می‌کند.

### ۹.۳ ویزارد اجرای اول

فایل `.deb` رابط گرافیکی ندارد؛ ویزارد با اولین اجرای `vpnctl-gui` از منوی دسکتاپ باز می‌شود. آرشیو portable هم همین رابط و یک entrypoint نصب دارد.

1. **خوش‌آمد** و راهنمای اتصال.
2. **گزینه‌های راه‌اندازی:** اجرا هنگام ورود، helper هنگام بوت و اتصال خودکار با در دسترس بودن گوشی.
3. پورت و نوع پروکسی در Settings قابل تنظیم‌اند (پیش‌فرض ۱۰۸۰۸).
4. پروکسی گوشی را از داشبورد آزمایش کنید؛ تأیید USB debugging باید روی خود گوشی انجام شود.

همه‌ی انتخاب‌ها بعداً در Settings قابل تغییرند؛ ویزارد با `vpnctl-gui --wizard` دوباره اجرا می‌شود.

### ۹.۴ سیاست وابستگی (نسخه‌ی صادقانه)

* **داخل بسته:** `tun2socks`، `adb`، همه‌ی آیکون‌ها و همه‌ی فایل‌های وب. باینری‌های Go استاتیک‌اند.
* **داخل بسته نیست و روی میزبان لازم است:** `iproute2`، پشتیبانی TUN هسته، systemd، polkit (پنجره‌ی رمز `pkexec`)، systemd-resolved برای DNS-over-TLS و مرورگر. بدون systemd-resolved، DNS-over-TLS در دسترس نیست؛ fallback محدود resolv.conf بدون TLS کار می‌کند.
* بنابراین `.deb` خط `Depends:` خالی دارد؛ نبودن یک تکه‌ی اختیاری پیام روشن می‌دهد و نصب را خراب نمی‌کند.

### ۹.۵ حذف نصب

`vpnctl uninstall` بستهٔ Debian را حذف می‌کند و `vpnctl uninstall --purge` فایل تنظیم سیستم را هم پاک می‌کند. عملیات از `dpkg` و درخواست مجوز استاندارد polkit استفاده می‌کند و `prerm` تلاش می‌کند تونل فعال را برگرداند. این فرمان نصب portable را حذف نمی‌کند و تنظیمات/autostart کاربر را عمداً نگه می‌دارد. فایل `sudoers` ساخته نمی‌شود.

## ۱۰. مدل امنیتی

* فقط یک پردازش دارای دسترسی ویژه (`vpnctld`)؛ بقیه بدون دسترسی ویژه‌اند.
* root فقط از طریق **polkit/pkexec**؛ **بدون sudoers بدون رمز**، بدون باینری setuid.
* سوکت یونیکس با اعتبارنامه‌ی همتا (`SO_PEERCRED`) احراز می‌شود: فقط کاربر نصب‌کننده (و گروه `vpnctl`) می‌تواند به helper دستور بدهد.
* helper فقط باینری‌های خودش را با مسیر مطلق و آرگومان‌های ثابت اجرا می‌کند؛ پورت‌ها و مقدارهای DNS اعتبارسنجی می‌شوند (بدون shell و بدون چسباندن رشته).
* سرور رابط فقط روی localhost با توکن و بررسی `Origin`.
* انتشارها با checksum و امضا عرضه می‌شوند.
* نکته‌ی حریم خصوصی: وقتی کانفیگ VPN **رایگان** است، صاحب آن کانفیگ می‌تواند ترافیک رمزنشده را ببیند. همه‌جا HTTPS استفاده کنید و ورود به حساب‌های حساس را از کانفیگ رایگان انجام ندهید.

## ۱۱. درس‌های تست میدانی

این موارد از تست واقعی روی یک لپ‌تاپ Linux Mint با گوشی اندروید آمده‌اند و حالا نیازمندی طراحی هستند:

| مشاهده | نتیجه در طراحی |
|---|---|
| پروکسی PdaNet+ هیچ‌وقت بالا نیامد؛ فقط پورت‌های v2rayNG (۱۰۸۰۸/۱۰۸۰۹) دیده شدند. | هدف، پروکسی SOCKS محلی گوشی است؛ وابستگی به PdaNet نیست. |
| اسکریپتی که رابط را با الگوی نام (`enp*`) انتخاب می‌کرد، کارت شبکه‌ی سیمی را برداشت نه USB را. | هرگز با حدس از روی نام انتخاب نمی‌شود؛ vpnctl اصلاً به رابط tether نیاز ندارد (از `adb forward` استفاده می‌کند). |
| پورت `127.0.0.1:10808` روی گوشی فقط loopback است و از طریق tethering در دسترس نیست. | انتقال با `adb forward` انجام می‌شود. |
| متغیرهای `HTTP_PROXY`/`ALL_PROXY` در شل باعث شد تست بدون استفاده از تونل موفق شود. | `up` متغیرهای پروکسی را چک و هشدار می‌دهد؛ تست‌ها در سطح سوکت‌اند و به `curl` و env اعتماد نمی‌کنند. |
| TCP کار می‌کرد ولی DNS (UDP) از طریق SOCKS timeout می‌شد. | DNS به‌صورت پیش‌فرض روی TLS/TCP می‌رود (`dns_over_tls = true`). |
| دوبار اجرای `vpn-up` خطای `create tun: device or resource busy` داد. | `up` تکرارپذیر است و وضعیت نیمه‌کاره را اول پاک می‌کند. |
| Ctrl-C روی `tun2socks` پیش‌زمینه، default route را روی یک `tun0` مرده جا گذاشت. | پردازش پس‌زمینه‌ی نظارت‌شده + watchdog + بازگردانی خودکار. |
| `tun2socks` در این نسخه فلگ بلند با یک خط تیره را قبول نکرد. | از شکل `--flag` استفاده می‌شود (نسخه‌ی قفل‌شده، با تست پوشش داده می‌شود). |
| IP و کشور خروجی در طول زمان عوض شد (کانفیگ‌های رایگان می‌چرخند). | IP/کشور خروجی زنده نمایش داده می‌شود؛ هیچ فرضی نمی‌شود. |
| پاسخ IPv6 دیده شد در حالی که IPv6 از تونل عبور نمی‌کرد. | هنگام اتصال، IPv6 یا خاموش می‌شود یا کامل مسیردهی می‌شود. |

## ۱۴. ریسک‌ها و تصمیم‌های باز

1. **بسته‌بندی `adb`.** سورس adb متن‌باز است (Apache-2.0)، ولی شرایط توزیع مجدد باینری آماده‌ی *platform-tools* گوگل باید بررسی شود. گزینه‌ها: ساخت adb از سورس، یا استفاده از نسخه‌ی توزیع لینوکس. در فاز ۶ تصمیم گرفته می‌شود؛ کد از یک لایه‌ی انتزاع استفاده می‌کند تا باینری قابل جایگزینی باشد.
2. **«بدون فریم‌ورک گرافیکی» و مرورگر.** پنجره یک صفحه‌ی وب است، پس به یک مرورگر نصب‌شده نیاز دارد (هر دسکتاپی دارد). برای حالت بدون سر (headless): CLI و یک رابط ترمینالی اختیاری.
3. **Tray در GNOME.** افزونه‌ی AppIndicator لازم است؛ پنجره بدون آن هم کار می‌کند.
4. **`.deb` خودش نمی‌تواند پنجره نشان دهد.** به همین دلیل ویزارد اجرای اول (بخش ۹.۳) وجود دارد. اگر وسط `dpkg` پرسش بخواهید، فقط سؤال متنی `debconf` ممکن است.
5. **DNS.** اولویت با systemd-resolved است؛ fallback محدود به resolv.conf معمولی پشتیبانی می‌شود. DNS-over-TLS به systemd-resolved نیاز دارد.
6. **تأیید USB debugging.** اتصال اول نیاز به یک لمس روی گوشی دارد (*Allow USB debugging*)؛ ویزارد راهنمایی می‌کند.
7. **شرایط توزیع اجزای ثالث.** NOTICE مربوط به Google platform-tools در artifactها قرار می‌گیرد؛ پیش از انتشار bundle حاوی adb، maintainer باید شرایط بازتوزیع را بررسی کند.
